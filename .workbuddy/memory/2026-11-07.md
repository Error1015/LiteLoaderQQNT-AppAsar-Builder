# 2026-11-07

## create_asar：QQNT 9.9.37 app.asar 注入 LiteLoader（MakeQQGreatAgain）

**结论：注入点必须是 `QQNT\versions\<ver>\resources\app.asar`（resources 根目录，与 app 目录同级），不能改 `resources\app` 内任何文件。**

### 反推出来的启动链路（QQ 9.9.37-54395）
1. `QQ.exe` 原生层启动前校验：`resources\app\application.json` 里存着 `application.asar / wrapper.node / major.node / package.json` 的签名摘要，校验失败直接静默退出，控制台打印 `error code v2:-1`。
   - 改 `resources/app/package.json` 的 `main` → 静默退出（实测，哪怕 main 指向普通 js 文件也一样）。
   - 删掉 `application.json` → 同样 `v2:-1`，说明"清单缺失=篡改"。
   - `package.json` SHA256 = `ac12d1b1…423b6d`（64 hex），但期望值不在 exe/dll 里以 ASCII 或原始字节出现，属于签名制，无法本地伪造。
2. `application.asar` 内的文件全部**逐文件加密**（`fs` 层由 QQ 打过补丁，读时按 `getPlain` 解密），所以绝不可重打包 —— 会出现 `Cannot find module` 或完整性校验失败。
3. Electron 侧应用根目录优先取 `resources\app.asar`（存在即用它，`resources\app` 整目录被忽略）。

### 因此 app.asar 内部结构（可用）
```
package.json            -> main: ./app_launcher/index.js
app_launcher/index.js   -> require(加载器) → 兜底 require QQ 本体入口
application/background.js -> require(process.resourcesPath/app/application.asar/background.js)
```
第三项是关键：QQ 原生启动器（app_launcher/launcher.js）会按 `app.getAppPath()` 拼 `<appPath>/application/background.js` 加载主进程主体；asar 成为应用根后该路径落到 asar 内，必须放转发壳，否则 QQ 报 `CAUGHT MAIN PROCESS ERROR ... Cannot find module`。

### 其它坑
- 加载器 `D:\App\LiteLoaderQQNT`（mqga）的 `src/main.js` 自己会 require 本体入口 `./application.asar/app_launcher/index.js`，所以壳里不要再无条件第二次 require；用 `require.cache` 判断。
- QQ 自更新会重建 versions 目录，注入会丢，需重新 `node install.js`。
- 环境变量 `LQ_INJECT_DISABLE=1` 可跳过宿主，直接原生启动（应急）。

### 项目脚本
- `node build-asar.js` → 生成根目录 `app.asar`（`--loader=`/`--qq=` 可覆盖路径）
- `node install.js` / `--status` / `--restore`
- 备份：`backup/`（含原始 package.json 与旧 asar）

### backup/ 维护约定（清理时必读）
- **必须保留**：`application.json.bak`（QQ 原生完整性清单，application.asar/wrapper.node/major.node/package.json 的签名摘要，是修复 `v2:-1` 的唯一凭据）、`package.json.*.bak`（原生 `resources/app/package.json`，`main` 为原生入口）。
- **可清理**：`install.js` / `--restore` 每次都会新增 `app.asar.<时间戳>.bak`，同一版本会累积大量完全相同的副本 —— 用 `md5sum` 去重，每组只留一份；与根目录当前 `app.asar` md5 相同的备份可直接删。
- 分发本项目给别人时，根目录 `app.asar` 不能直接复用：`__LQ_LOADER_PATH__` 已写死构建时的宿主路径，对方宿主装在别处须自行 `build-asar.js --loader=`。
